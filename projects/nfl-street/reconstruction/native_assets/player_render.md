# Native player rendering from the draw submission

`gx_render.c` executes the GX calls that `player_draw.c` produces (the
original `80161E10` submission, `player_draw.md`) in a small software GPU.
`player_render_check.c` uses it to draw the 14 players of a saved context
natively. The scene is not drawn. The calls, display lists, skinning
matrices, texture objects and palettes are exactly what the original would
use. The executor turns them into pixels.

This is an inspection renderer. The draw submission is verified against the
original; the pixels are not claimed to be the original's.

## What the executor does

It keeps GX state from the calls and runs display lists:

- **Matrix loads.** Indexed loads A/B fill transform memory from the skinning
  palette (`GXSetArray` 0x15/0x16). In the players' lists, each bone is one
  3×4 position load and three 3-float normal-row loads, so stride 0x10 picks
  the matrix rows.
- **Vertices.** Indexed or direct vertices (position, normal, color, texture
  coordinates in any GX component type). The per-vertex matrix index
  selects the position matrix, and the normal matrix comes from `0x400 +
  3·(index & 31)`.
- **Transform.** Positions go through the eye-space matrix, then the
  projection (`GXSetProjection` perspective: `x·p0 + z·p1`, `y·p2 + z·p3`,
  `z·p4 + p5`, `w = −z`).
- **Lighting.** One color channel, as the public GX model and the local
  Dolphin reference (`LightingShaderGen`) define it. Ambient plus each
  light's color × clamped N·L, with no attenuation, clamped, then
  `material × (light + light>>7) >> 8`.
- **Texture coordinates.** Generated by 2×4 matrices from TEX0, including
  the eye texture matrices.
- **Rasterizing.**
  - Clipping against the GX clip volume (`−w ≤ z ≤ 0`).
  - Culling on the clip-space winding, using Dolphin's `CPUCull` rule. The
    players' `GXSetCullMode(1)` is hardware "front" and culls winding ≤ 0.
  - Perspective-correct interpolation.
  - Viewport mapping, with the depth range the draw sets.
- **TEV.** Integer stages with Dolphin's lerp formula:
  `(d + bias) ± ((a·256 + (b − a)·(c + c>>7)) << s + 128) >> 8`.
  - Inputs: prev, registers, texture, raster, konst (with the 1…1/8
    fractions) and the constants.
  - Ops: add or subtract, with bias, scale and clamp.
  - The OnePass and TwoPass presets need nothing more.
- **Per pixel.** Alpha compare, depth test and update (24-bit), and blend
  modes none, blend and subtract.
- **Textures.**
  - Formats: I4, I8, IA4, IA8, RGB565, RGB5A3, RGBA8, CI4, CI8, CI14 and
    CMPR, with IA8/RGB565/RGB5A3 TLUTs from the TLUT objects.
  - Mip levels follow the base image, each padded to whole tiles.
  - LOD comes from the screen-space coordinate derivatives plus the object's
    bias (mode0 bits 9–16), clamped to its min/max LOD.
  - Filtering follows mode0: the player textures use bilinear filtering
    within the nearest mip, with bias −1.3 from `80164DD8`.

The player draw does not set some frame state. Projection, viewport, color
mode and konst selections come from the saved GX shadow (`r13-4C90` +0x420,
+0x43C, +0x1D0, +0x1B0). Depth mode and texgen sources come from the frame
start `801C769C`: `GXSetZMode(1, LEQUAL, 1)` and every coordinate MTX2x4
from TEX0 with the identity. The shadow only shows the state left by the
last draw. Context 15 was saved with depth off, which would have been wrong
for players.

Not modeled: fog, indirect textures, swap tables, the second color channel,
logic ops, anisotropy, diagonal LOD and EFB copies.

## Evidence

```bash
PYTHONPATH=projects/nfl-street/reconstruction/menus \
  python3 projects/nfl-street/reconstruction/native_assets/verify_player_render.py
```

The gate first requires the passed, source-matched player-draw report. It
then renders contexts 14, 15 and 16 twice each in fresh Windows processes.

- **Native draw state matches the earlier GPU recording.** That recording
  is the 2026-10-08 Dolphin FIFO capture of an original frame
  (`original_render_capture.md`). Its 557 player draws have two distinct
  one-stage states once the texture mode is set aside. At every native
  display list, the check encodes the state with the SDK's own bit layouts
  (`8020791C`, `80206F1C`/`80206FA4`, `80206F60`/`8020700C`, `80207320`,
  `80205400`):
  - depth mode `0x17`;
  - blend `0x54B8`/`0x54B9`;
  - TEV color/alpha stage 0 `0x18F8AF`/`0x18F2F0`;
  - alpha compare `0x3F0000`/`0x3C0000`;
  - white material and ambient `0x2D2D3280`;
  - channel `0x51E` (three lights).

  Both recorded states are produced by the native calls. The native calls
  produce no other one-stage state. The real hardware registers therefore
  agree with the native reading of the OnePass shader, the blend and
  alpha-compare presets, the lighting channel and the light set.
- **Independent texture decoding.** All 337 non-empty slot textures of the 14
  captured players (4,221,952 pixels) decode identically two ways. The GX
  decoder works from the texture object and TLUT object. The existing MMAP
  reader (`texture.c`) works from the slot's destination file, after its
  header and descriptor pointers are turned back into file offsets.
- **Repeatable images.** The images repeat exactly. Context 14 has 19,631
  triangles (9,955 culled as back faces) and 22,295 covered pixels.

**Visual comparison (inspection only).** The uniforms, numbers, skin,
headbands, shoes and poses match the game's screenshots. Positions match
closely, but the snapshot RAM and its saved screenshot are not always the
same frame: the context-14 render lines up better with the screenshots
saved for contexts 15 and 16. Lighting looks slightly brighter than the
displayed image, which also passes through the video output.

## Players on the field

The same check also renders a scene. It draws the EARS field passes and main
field through the verified native scenery draw (`scenery_draw.md`), then the
14 players, into one target with shared depth, from a fresh copy of the saved
RAM. This follows the original frame order: passes, decals, main field, ball,
players. The decals, ball, sky, crowd, shadows and HUD are not drawn. The
field shows the grass and its mowing stripes, the wall, trees and buildings,
and the players stand on it with correct occlusion. Images:
`scene-14/15/16.bmp` (context 14: 26,244 triangles, 640,107 shaded pixels).
Compared with the game's screenshot, the missing pieces are exactly the
unmodeled ones: sky, HUD, the yellow and blue lines, the target ring and the
shadows.
