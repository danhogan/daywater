# Score writer at `0x80104294`

**Status:** writer and adjacent clear function byte-matched; portable semantic C candidates retained.  
**Target:** NFL STREET GameCube `GNNE69`, North America revision 0, DOL SHA-1
`46e3de854998a0f66c9be8c72a1164d22cd29eb4`.  
**Evidence confidence:** `verified` static field writes and live execution
during two separate observed 6→7 PAT conversions; `candidate` original C
source and names.

The 52-byte function immediately follows the score reader in DOL text
section 1 at file offset `0x101294`. The 13 instructions have the following
control flow:

| Address | Instruction | Observed effect |
|---|---|---|
| `0x80104294` | `cmpwi r3, 1` | Compare side argument with 1. |
| `0x80104298` | `bne 0x801042A8` | Side other than 1 branches to right score. |
| `0x8010429C` | `lwz r9, -0x7078(r13)` | Load match object pointer. |
| `0x801042A0` | `sth r4, 0x3E(r9)` | Store low 16 bits in left score. |
| `0x801042A4` | `b 0x801042B0` | Join the paths. |
| `0x801042A8` | `lwz r9, -0x7078(r13)` | Load pointer on right-score path. |
| `0x801042AC` | `sth r4, 0x3C(r9)` | Store low 16 bits in right score. |
| `0x801042B0` | `cmpwi r4, 0` | Compare the full input value with zero. |
| `0x801042B4` | `beqlr` | Return immediately if zero. |
| `0x801042B8` | `lwz r9, -0x7078(r13)` | Reload match object pointer. |
| `0x801042BC` | `li r0, 1` | Prepare value 1. |
| `0x801042C0` | `stw r0, 0x40(r9)` | Set a 32-bit field at object +0x40. |
| `0x801042C4` | `blr` | Return. |

The field at `+0x40` is left as `unknown_40` in `score_fields.h`. The code
proves it is assigned 1 for nonzero input values, but its broader game
meaning is not verified. In particular, the comparison uses the full `r4`
input even though `sth` stores only its low 16 bits. For an input such as
`0x10000`, the stored score becomes zero while `unknown_40` is set to 1;
the C candidate preserves that behavior.

The adjacent 16-byte function at `0x801042C8` writes zero to the same
`+0x40` field. It is modeled portably in `clear_unknown_40.c`. Static callers include
`0x8002676C`, which calls it before reading, calculating, and writing a new
score, and `0x80004E4C`, which calls it after copying table values to the
score fields. The field was 1 in the saved 6–0 and 7–0 states, but zero in a
later 0–17 match capture. These observations rule out treating it as a
persistent “has ever scored” value; its precise role is still unknown.

Check the original DOL and C syntax locally:

```bash
python projects/nfl-street/reconstruction/verify_score_targets.py \
  cache/extracted/<iso-sha1>/boot.dol writer
python projects/nfl-street/reconstruction/verify_score_targets.py \
  cache/extracted/<iso-sha1>/boot.dol clear
gcc -std=c89 -Wall -Wextra -Werror -fsyntax-only \
  projects/nfl-street/reconstruction/score_writer/score_writer.c \
  projects/nfl-street/reconstruction/score_writer/clear_unknown_40.c
```

Zig/Clang 21.1.0 generated PowerPC assembly with the two score-store paths,
conditional early return, and `+0x40` write. It hoists the pointer load and
uses an absolute-address global load, unlike the original `r13` path. The
original portable clear candidate similarly uses five instructions instead of
four. See [toolchain.md](../toolchain.md) for commands and retained assembly.
Those initial, unconstrained writer builds did not byte-match.

The separate `score_writer_gcc_match.c` now reproduces all 52 writer bytes
with GCC 15.2.1 PowerPC output. It uses the verified `r13-0x7078` pointer
slot, explicit `r9` and `r0` registers, and empty assembly constraints that
add no instructions. GCC options disabling block reordering, if-conversion,
and instruction scheduling retain the original side-1 fallthrough branch,
two `sth` paths, and shared `beqlr` return. `build_score_matches.sh`
assembles the output, rejects `.text` relocations, and compares the extracted
bytes with the hash-checked DOL. The result is a byte-for-byte match with
SHA-256 `fdea0f82363ab97caa73b3abd6c03cb672a583f12cea6b4c5ada8534cb4aaeaf`.
This demonstrates one source representation of the machine code; it does not
identify the original compiler, source syntax, or role of `unknown_40`.

The separate `clear_unknown_40_clang_match.c` reproduces the clear function's
four instructions exactly with Clang 21.1.0 and explicit PowerPC register
constraints. `build_clear_match.sh` extracts the object's relocation-free
16-byte `.text` and compares it with the hash-checked DOL; the match passed.
This verifies the generated bytes, not the game's original compiler or source
syntax. The portable `clear_unknown_40.c` remains the host-test version.
